# 1. Team Formation Overview

The team was formed with the goal of developing a **Minimum Viable Product (MVP)** that solves a real-world problem using modern web technologies. Each team member contributes to the project through specific roles to ensure effective collaboration and project delivery.

## Team Roles

### Project Coordinator
- Oversees the project timeline and ensures milestones are met.
- Facilitates communication between team members.
- Ensures the project aligns with the requirements of the program.

### Frontend Developer
- Responsible for building the user interface.
- Implements responsive design and ensures good user experience.
- Integrates frontend components with backend APIs.

### Backend Developer
- Develops the server-side logic.
- Designs and manages APIs.
- Handles authentication, data processing, and system logic.

### Database & System Design
- Designs the database schema.
- Ensures efficient data storage and retrieval.
- Maintains data integrity and performance.

## Collaboration Strategy

To ensure effective collaboration, the team follows these practices:

- Weekly meetings to review progress and plan tasks.
- Task distribution based on each member’s strengths.
- Use of version control (Git) for code collaboration.
- Continuous discussion during the idea evaluation and development process.

# 2. Ideas Explored

During the brainstorming phase, the team explored several potential project ideas. Each idea was evaluated based on **feasibility, innovation, technical complexity, and the limited timeframe of the project**.

---

# Idea 1: Blood Donation Platform

## Concept
A platform that connects **blood donors with hospitals and patients in need of blood donations**. The system would allow users to register as donors, track their eligibility to donate blood, and receive notifications when someone nearby requires a specific blood type.

## Strengths
- Addresses an important social and healthcare issue.
- Could help improve response time in emergency situations.
- Encourages community engagement and awareness about blood donation.

## Weaknesses
- Requires integration with **hospitals and healthcare institutions**, which may not be accessible during the project timeframe.
- Would require **real-time location tracking and verification systems**, increasing complexity.
- The system may require **strict data validation and medical compliance considerations**.

## Reason for Rejection
Although the idea has strong social impact, the team determined that it would require **external partnerships with hospitals or medical organizations**, which is difficult to implement within the limited duration of the project. Additionally, ensuring reliability and accuracy for a healthcare-related system would significantly increase development complexity.

---

# Idea 2: Product Price Comparison Platform

## Concept
A platform that allows users to **compare prices of products across multiple stores or online retailers**. Users could search for a product and view where it is available at the best price.

## Strengths
- Highly useful for consumers.
- Encourages transparency in product pricing.
- Could help users save money by finding the best deals.

## Weaknesses
- Requires **access to product data from multiple stores**, which may not be publicly available.
- Would likely require **web scraping or API integrations**, which can be unstable or restricted.
- Maintaining accurate and up-to-date pricing information would be technically challenging.

## Reason for Rejection
The team concluded that this idea would require **data integration from multiple external sources**, which may not provide open APIs. Implementing web scraping solutions could also introduce legal or technical limitations. Due to the **dependency on third-party data and the complexity of maintaining real-time accuracy**, this idea was not considered feasible within the project timeframe.

# 3. Selected MVP Concept

## Veterinary Consultation & Pet Adoption Platform

### Concept Summary
The selected MVP is a **web platform that connects pet owners with veterinarians for online consultations** while also providing a space for **pet adoption listings**.

The platform will allow users to:

- Register either as **pet owners or veterinarians**.
- Search for veterinarians.
- Communicate with veterinarians through **online messaging or video consultations**.
- Browse animals available for adoption and contact the person responsible for them.

The system aims to simplify access to veterinary advice while also helping animals find new homes through adoption.

---

## Reasons for Selection

### 1. Feasibility
Unlike the previous ideas, this concept does not depend heavily on **external institutions or third-party data sources**. The core features can be implemented entirely within the development team's control.

### 2. Technical Suitability
The project allows the team to implement multiple modern web development concepts, including:

- User authentication
- Real-time messaging
- Database management
- Search functionality
- Role-based user systems

This makes it a strong technical project for demonstrating development skills.

### 3. Innovation
Combining **veterinary consultation services with a pet adoption platform** creates a more comprehensive system that benefits both pet owners and animals in need of homes.

### 4. Alignment with Learning Goals
The project aligns well with the course objectives by requiring:

- Full-stack web development
- System design and architecture
- User-centered design
- Collaboration within a development team

# Potential Challenges

During brainstorming, the team identified several possible challenges:

- Implementing reliable **real-time communication features**.
- Designing a scalable database structure for users, pets, and messages.
- Ensuring a simple and user-friendly interface.

However, these challenges were considered manageable and valuable learning opportunities.
